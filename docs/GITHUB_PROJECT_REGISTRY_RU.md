# Независимые GitHub-проекты, ветки и образы в YadroKreator

## Новая навигация

Раздел верхнего уровня **«Образы T23N» упразднён**: открой **WIFICAM T23N → Образы и SD**. Там же, рядом со сборками WIFICAM, находятся её артефакты, SHA256 и кнопки «Проверить SD»/«Скачать образ .img». Эталон `0.1_test` отображается с обозначением «старый образ для отката», **не считается результатом новой сборки**.

Irila Baikal имеет свою вкладку, аудит исходников и ссылку на её независимый GitHub Actions IMG. WifCam Helper — свой диагностический сервис и SQLite-отчёты, **не** компилятор ядра.

## Добавление ветки для настоящей сборки T23N

Открой **Система → Подключение веток и независимых проектов → Новая ветка WIFICAM T23N**. Введи, например, `feature/new-kernel` (такая ветка должна *реально* существовать в `musikfed/wificam_T23N`). Подтверди. Сервер выполняет **только** `git ls-remote` к зафиксированному GitHub-репозиторию (без скачивания кода и без выполнения сценариев), затем сохраняет допущенную ветку в закрытом локальном файле `/1tbdisk/PegineLab/factory-state/registered-projects.json`. После этого в **WIFICAM → Сборки и журнал** можно выбрать эту ветку и собрать её штатным проверенным T23N-профилем; фабрика закрепляет точный SHA в отдельном worktree каждого job и не загружает старый Git-эталон как новый кандидат.

Важно: Helper-профиль `t23n_lean.json` утверждён пока только для `mymarrchWFcam`. На других ветках выключается автоматически, а сборка использует независимый обычный профиль T23N. Новая ветка сама по себе **не появляется как отдельный проект**: у неё та же архитектура камеры, компилятор и семейство образов.

## Новый GitHub-репозиторий → новая вкладка

Открой **Система → Новый проект**. Укажи название для меню, короткий ID для URL, репозиторий строго `musikfed/REPO` и реально существующую ветку. GitHub проверяется чтением `ls-remote`. Создаются:
- Собственная вкладка в левом меню и карточка на главной.
- **Исходники и GitHub** — ссылка на конкретный репозиторий/ветку и кнопка проверки текущего SHA.
- **Сборки и очередь** — статус готовности адаптера.
- **Образы проекта** — собственное пространство; **никаких чужих .img**.
- **Журналы** и **Конфигурация** — место для отдельного пайплайна и профиля.

**Новый проект по умолчанию в состоянии `pending_adapter` и НЕ собирается.** Это осознанная защита сервера: репозиторий Linux-ядра сам по себе не даёт достоверных сведений об архитектуре, defconfig, toolchain, buildroot, формате IMG/ISO или способе проверки. Чтобы включить его, требуется ревью нового адаптера через GitHub YadroKreator с тестами, безопасными путями, собственным systemd-job, логом, кешем и проверяющим сборку валидатором. Никаких `eval` или запусков чужого `build.sh` напрямую из веб-формы. Предыдущие профили `t23n_sd` и `irila_preflight` не меняются.

## Изоляция данных

Registry JSON: `/1tbdisk/PegineLab/factory-state/registered-projects.json` (0600); фабричная SQLite: `factory-state/factory.sqlite3`. Старые jobs сохраняются на месте и их `profile`, `repo_ref`, `source_sha` не мигрируют автоматически. Новые проекты **не присваивают себе** уже существующие job или образы. Максимум 20 регистрируемых проектов и 25 дополнительных веток WIFICAM. Редактировать JSON вручную при работающей панели нежелательно; пользуйся формой. Доступ к регистрации — **только доверенная LAN/VPN** плюс защитный заголовок и подтверждение. Это сетевой барьер, а не пользовательская аутентификация: не открывать :62404 в WAN.

## Установка из Git через SSH

На Huananzhi, без `sudo`, при отсутствии активных сборок:

```bash
cd /1tbdisk/PegineLab/projects/YadroKreator
git status --short
bash deploy.sh --check
bash deploy.sh --apply

# После появления нового кода:
bash scripts/rebuild-from-git.sh --check
bash scripts/rebuild-from-git.sh --apply --clean-cache
```

Полное обновление означает: Git fast-forward, проверка базы SQLite с резервной копией, установка зависимостей, все Python/JS проверки, очистка только подтверждённого кэша панели и перезапуск user-service `peginelab-factory.service` с HTTP health-check. **Проект не использует обязательные Docker-контейнеры, поэтому пересобирать или удалять Docker-образы НЕ требуется.** Команды `docker system prune`, `docker image prune -a`, `docker volume prune` запрещены в этой операции: они затронут другие проекты на том же сервере.

Проверка после обновления: `http://192.168.0.100:62404/`, WIFICAM → два внутренних раздела, отсутствие отдельной «Образы T23N» в меню, форма подключения проекта в «Система» и новый GitHub-проект после его регистрации. Ни сборку ядра, ни запись microSD обновление панели само не начинает.
