# YadroKreator — один рабочий экран на каждое ядро и прошивку

## Единый интерфейс

Одна вкладка = один сборочный проект. На одной странице: Git-источники, «Создать», «Проверить», «Скачать», «Удалить», история заданий, список образов и отдельная консоль логов.

**WIFICAM T23N:** выбирает Git-ветку, создаёт SD-образ на Huananzhi, сохраняет job ID и source SHA, проверяет SHA256/MBR/MSPL LBA34/FAT16/uImage/ext4, затем скачивает .img после повторной проверки. Эталон 0.1_test защищён и никогда не считается новой сборкой.

**Irila Baikal:** «Создать IMG · GitHub» вызывает только утверждённый workflow build-installed-full-secureboot-img.yml в musikfed/Irila_baikal_v1.0/main через уже авторизованный gh CLI на CORE. Локальная «Проверить» создаёт отчёт аудита источников, а не IMG. Список GitHub Actions артефактов и ссылки на их журналы загружаются по запросу. Готовое IMG остаётся в GitHub Actions, откуда его можно скачать.

**WifCam Helper:** третья **самостоятельная SD-прошивка T23N**. Собирается в собственном дереве из двух закреплённых SHA: Helper main и WIFICAM mymarrchWFcam. Внутри ext4 реально находятся init/probe/CGI файлы Helper. На его вкладке — «Создать», «Проверить», «Скачать», отдельные история, логи и образы. Диагностический Python-стенд находится внутри этой же вкладки в раскрываемом блоке для тестов после физической прошивки.

**Новые проекты:** роль build требует PegineLab Project Contract v1. До утверждения адаптера видны отключённые кнопки «Создать / Проверить / Скачать» без фиктивного исполнения.

## Удаление файлов

**Локальный артефакт:** только конкретный UUID завершённого задания, два подтверждения. Удаляется исключительно его собственный файл результата и sidecar SHA256/проверка. Исходники, эталон Thingino/thingino-t23-sd.bin, чужие файлы, журналы и SQLite история сохраняются. Запись удаления и освобождённые байты сохраняются в artifact_events. Ошибочные сборки остаются в списке с причиной отказа и журналом, но без фиктивного скачивания.

**GitHub Actions:** это временные workflow artifacts, а не Git-коммиты или исходный репозиторий. Список читается из GitHub через gh CLI по точному репозиторию. Удалить можно только точный artifact ID с двойным подтверждением. Git history, ветки, релизы, workflow и исходники НЕ удаляются. Удалённый архив можно воспроизвести только при сохранённом Git SHA, доступных зависимостях и исправном workflow; обещать любую пересборку нельзя.

Управление GitHub не требует токена в YadroKreator UI, но на CORE под пользователем службы должен быть авторизован GitHub CLI:

```bash
gh --version
gh auth status
gh api 'repos/musikfed/Irila_baikal_v1.0/actions/artifacts?per_page=1'
```

Когда gh недоступен, интерфейс сообщает об этом и предлагает открыть GitHub Actions вручную. Удаление GitHub по умолчанию отключено. Только явное включение PEGINELAB_GITHUB_ARTIFACT_DELETE=1 в локальном окружении systemd службы позволяет использовать кнопку удаления. Права GitHub Actions:read нужны для просмотра, Actions:write — для запуска и удаления. Не хранить токены в публичных репозиториях.

## Где лучше проводить проверку

GitHub CI полезен для тестов исходников, воспроизводимой сборки и статуса workflow. Но проверка бинарной структуры .img привязана к платформе (для T23N она на Huananzhi), а физический Wi-Fi, микрофон, динамик и SC2336 проверяются только на реальной камере и через WifCam Helper. Успешный GitHub Actions не доказывает, что образ загрузится на устройстве.

## Обновление

После зелёного CI и объединения PR в main, по SSH:

```bash
cd /1tbdisk/PegineLab/projects/YadroKreator
bash deploy.sh --check
bash deploy.sh --apply
bash scripts/rebuild-from-git.sh --check
bash scripts/rebuild-from-git.sh --apply --clean-cache
```

Никаких глобальных Docker prune, удаления других баз, исходников или прошивки камеры. Для устаревших frontend-файлов в браузере после обновления нажать Ctrl+F5.
