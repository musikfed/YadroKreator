# Проверка прошивки перед записью SD — PegineLab

## Что означает зелёная проверка

В разделе **Сборки** выберите успешно завершённое задание WIFICAM T23N (профиль \`t23n_sd\`) и нажмите **«Проверить образ перед записью SD»**. Эта кнопка **только читает** файл из каталога выбранного задания на Huananzhi. Никаких команд \`dd\`, \`mkfs\`, \`parted\` и записи на USB/SD нет.

Проверяем:

1. Файл действительно создан в выделенном worktree завершённой сборки. При ошибке или незавершённом задании кнопка неактивна. Пути от браузера не принимаются.
2. Реальный SHA-256 всего файла равен его \`.sha256\` sidecar. Если sidecar отсутствует, проверка завершается ошибкой.
3. DOS/MBR имеет сигнатуру \`55 AA\`; секторы кратны 512 байтам.
4. T23N MMC SPL/MSPL находится **строго на LBA34**, имеет ожидаемую сигнатуру \`4d53504c\`.
5. Раздел **p1** начинается LBA2048, имеет 32768 секторов (16 МиБ), FAT16 LBA тип \`0x0E\`; BOOT содержит FAT-запись \`/uImage\` с правильной U-Boot magic \`0x27051956\`.
6. Раздел **p2** начинается LBA34816, имеет тип Linux \`0x83\`, не выходит за пределы образа, содержит сигнатуру ext4.
7. Сохраняем результаты в \`factory-state/validation/<job-id>.json\` с SHA, размером и mtime. Не заносим Wi-Fi ключи, содержимое образа или произвольные пути из запроса.

Если все проверки пройдены, появляется **динамическая SVG-карта** загрузчика, ядра и rootfs: \`/api/jobs/<id>/layout.svg\`. Пропорции на схеме условные, адреса — из фактически прочитанного образа.

**Это не означает**, что камера загрузилась, подключилась по Wi-Fi, передаёт RTSP или управляет PTZ. Такое подтверждается только тестом на физической T23N. Проверка структуры — отдельная ступень \`image-verified\`, не \`hardware-verified\`.

## Что делать при красной ошибке

- **SHA256 does not match**: файл изменён/повреждён; не записывайте на SD, проверьте журнал и пересоберите.
- **MSPL magic missing at LBA34**: нарушена загрузочная геометрия; запрещено компенсировать проблему добавлением \`seek=34\` при записи полного образа.
- **BOOT FAT16 has no /uImage** или **uImage magic**: ядро не найдено или неверно упаковано.
- **ROOTFS ext4 superblock**: неправильный rootfs; проверяйте скрипты формирования SD.
- **Validation stale**: файл изменён с момента проверки; нажмите «Проверить» повторно.

Проверка только для \`t23n_sd\`. Для ARM, UEFI, MIPS других SoC или отдельного ядра напишите отдельный валидатор с собственной проверенной картой памяти. Никогда не переиспользуйте LBA34 и FAT16 как общие правила.

## После проверки: запись и физический тест

На сервере найти SD-карту (сначала только чтение списка):
\`\`\`bash
lsblk -o NAME,PATH,SIZE,MODEL,TRAN,RM,MOUNTPOINTS
\`\`\`
Затем, только убедившись, что устройство — **съёмный USB-кардридер, а не системный диск**, использовать
\`wificam_T23N/scripts/write_thingino_wificam_sd.sh\` с **абсолютным путём к проверенному образу**. Скрипт записывает полный диск **с LBA0**, потому что MSPL **уже внутри образа** на LBA34. Не делать дополнительный \`seek=34\`.

После записи скрипт проверяет чтением записанных байтов SHA-256. На реальной камере отдельно проверять: SD boot, SSH/Dropbear, Web UI \`:8090\`, CGI/API, видео/RTSP, PTZ, восстановление после отключения питания и Wi-Fi. Только после аппаратной проверки можно объявлять \`0.2_test\` рабочим кандидатом для релиза.

## Время и прогресс

Начало — \`started_at\`, конец — \`finished_at\`, длительность = их разность (серверное время UTC, браузер показывает локальное). При работе отображается прошло времени. Для ETA используется **медиана последних пяти успешных сборок той же ветки и профиля**. До появления хотя бы одной успешной истории показывается анимация без процентов. Проценты — **временная оценка**, ограниченная 95% до фактического \`status=success\`. Сборка может идти дольше из-за исходников, загрузки сети или холодного кэша — это нормально. В панели явно написано, что фактический процент компиляции неизвестен.

## Команды независимой проверки на Ubuntu (только чтение)

\`\`\`bash
# Путь берите из раздела «Артефакты», а не из этого примера:
IMG="/ABSOLUTE/PATH/TO/out/private-sd/thingino-t23-sd.bin"
cd "$(dirname "$IMG")" && sha256sum -c "$(basename "$IMG").sha256"
od -An -tx4 -j $((34*512)) -N4 "$IMG"
fdisk -l "$IMG"
\`\`\`

Ожидаемую magic \`4d53504c\` и границы разделов проверяем **до** записи, не после её начала. Приватные образы не публикуем в GitHub/HTTP и не вкладываем в скриншоты или логи.
