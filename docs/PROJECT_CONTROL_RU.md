# YadroKreator — запуск / остановка панели, не сборок

**Что контролируем:** только веб-панель `peginelab-factory.service` на
Huananzhi Ubuntu 24.04 (`http://192.168.0.100:62404/`). Это отдельная
служба `systemd --user`; никаких Docker, sudo, reboot, остановки SSH или
запущенных `peginelab-build-*` задач.

## Управление из веб-морды (Обзор и Система)

В новой версии панели `http://192.168.0.100:62404/#overview`
в блоке **«Управление YadroKreator»** виден статус
`peginelab-factory.service`:

- **▶ Запустить (SSH)** — при доступной панели служба уже работает,
  кнопка неактивна. После полного выключения запуск выполняется только
  через локальный терминал Ubuntu или SSH. Веб-страница не может сама
  себя запустить после остановки.
- **↻ Перезапустить панель** — асинхронный `systemd --user restart`.
  Браузер восстанавливает соединение; активные фоновые задачи не
  завершаются.
- **■ Выключить панель** — с подтверждением. При работающей сборке
  кнопка заблокирована. Останавливается **только веб-служба**
  `peginelab-factory.service`, не весь сервер.
- **↓ Обновить из GitHub** — переходит на вкладку «Система». Там уже
  существуют «Проверить обновления», «Обновить панель», «Откатить».
  Это **настоящее обновление локальных файлов GitHub main на сервере**,
  выполняемое штатным проверенным updater с проверками и откатом,
  без отдельного `git reset --hard` из браузера.

Действия изменения службы ограничены существующей проверкой
доверенной LAN/VPN (`PEGINELAB_EXPORT_TRUSTED_NETWORKS`),
запрещают поддельные proxy-заголовки и чужой Origin, плюс используют
`X-PegineLab-Action`. По умолчанию допустимы loopback и
`192.168.0.0/24`. Если браузер из другой подсети получит
HTTP 403, добавить **только проверенную** VPN/локальную подсеть
в настройки окружения systemd, **не** `0.0.0.0/0`;
не публиковать открытый порт 62404 в Интернет. Это ограничение сети,
**не полноценная авторизация пользователя**.

**Важно:** изменения в GitHub не меняют автоматически программу,
запущенную на Huananzhi. Сначала открой существующую
**«Система → Проверить обновления → Обновить панель»**;
после установки появятся новые кнопки. Не останавливай
старую панель ради установки — для этого есть отдельный Git updater.

## На Huananzhi (Linux / SSH)

Из checkout `/1tbdisk/PegineLab/projects/YadroKreator`:

```bash
bash start.sh                             # запустить / Start
bash stop.sh                              # остановить / Stop
bash scripts/project-control.sh status    # статус / Status
```

Если исполняемые права не выставлены GitHub — используйте `bash`, как выше.
Скрипты работают только от **того же обычного Ubuntu-пользователя**, что
выполнял `bash install.sh`; от `root` запуск запрещён. Если службы ещё
нет, скрипт не создаёт её автоматически (первый раз используйте
`bash install.sh`).

**Остановка панели НЕ отменяет сборку прошивки**, выполняющуюся отдельным
systemd user unit. Для остановки задания используйте штатную кнопку
«Остановить» у конкретной сборки **до** выключения панели. После
`stop.sh` сайт исчезнет и не сможет сам себя запустить: старт через SSH
либо локальный терминал Huananzhi.

## С Windows PowerShell (через SSH на Ubuntu)

С компьютера, который видит `192.168.0.100`:

```powershell
.\start.ps1                       # запустить Linux-сервис по SSH
.\stop.ps1                        # остановить Linux-сервис по SSH
.\scripts\project-control.ps1 -Action status
```

Можно задать сервер: `.\start.ps1 -Server 'user@192.168.0.100'`.
Для входа подходит SSH-ключ или обычный пароль: при необходимости
Windows OpenSSH сам запросит пароль; сначала проверьте `ssh user@192.168.0.100` с Windows.
Скрипт не хранит и не спрашивает пароль в коде.

## Для текущей камеры

Остановка YadroKreator **не выключает T23N**: камера загружена с SD
`/dev/mmcblk0p2` и её отдельный PegineLab WIFICAM на порту
`:8090` ещё требует аппаратной проверки CGI.
YadroKreator — это сервер **сборки**, не робот и не работающая камера.
